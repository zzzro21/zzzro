# 퀄리티 체크리스트 — "시제품" 과 "작품" 의 차이

사용자가 보내준 원본 2편(대포 도록 페이지, "오늘 무슨 요일?" 30초)을 이 스킬의 첫 결과물과 나란히 놓고 뽑은 차이.
**납품 전에 이 표를 위에서부터 확인한다.** 하나라도 "시제품" 쪽이면 고친다.

| 항목 | 시제품 (우리가 처음 만든 것) | 작품 (원본) | 이 스킬에서 하는 법 |
| --- | --- | --- | --- |
| 1. 글꼴 | 지정했지만 렌더 PC 에 없어 **Inter 로 대체됨** (모르고 지나감) | 성격 있는 글꼴 2~3종이 실제로 렌더됨 | `templates/fonts.ts` 로 글꼴을 프로젝트에 포함 + 로딩 대기. 렌더 후 still 에서 글꼴 모양을 눈으로 확인 |
| 2. 화면 틀 | 빈 배경 위 요소만 | **프레임 장치**: 모서리 브래킷, 메타 정보 줄(`WEEKDAY.CHECK // JST`, `BAR 03 · BEAT 2`, 타임코드), 진행 막대 / 도록의 이중 테두리·장식·도판 번호 | 장르에 맞는 "틀" 을 먼저 정하고 모든 장면에 유지 |

| 4. 글자 체계 | 크기만 다른 한 글꼴 | 디스플레이(압축·세리프) + 모노/스몰캡 라벨(자간 넓게) + 이탤릭 주석 | 역할별 3단계: 주인공 / 라벨 / 주석 |
| 5. 데이터 | 답 하나만 보여줌 | **진짜 맥락 데이터**: 이번 주 달력(09.28–10.04), 몇 주차, 365일 중 며칠, "내일은 토요일" / 공기 중 vs 진공, 도탄 후 정지 거리 | 답 주변의 사실 3~4개를 계산해서 함께 보여준다 (지어내지 않고 계산) |

| 7. 전환 | 페이드·하드컷 | 의미 있는 전환: 스캔 상자가 정답으로 이동, 흰 플래시 1번, 줌인으로 다음 장면 | 전환마다 "앞 장면의 무엇이 다음 장면이 되는가" 를 정한다 |
| 8. 3D 배치 | 하늘·땅 상자 안에 모델 | 모델이 **페이지 위에** 서 있고 흙이 종이에 번짐, 그림자만 받는 바닥 | `ShadowNodeMaterial` + 투명 캔버스 + 가장자리가 흐린 바닥 |

## 납품 전 3단계 검사

1. **컨택트시트**: 장면마다 1장. 위 표 1~5 를 눈으로 확인 (특히 글꼴).
2. **원본 비교**: 레퍼런스가 있으면 같은 시점 프레임을 나란히 놓고 표 전체를 다시 본다.
3. **성능**: 반투명 입자가 화면을 겹겹이 덮으면 휴대폰에서 끊긴다 → 입자 수·크기 상한, 노이즈 옥타브 2 이하.

## 사례에서 확인된 함정

- DOM 위치를 읽어 배치하면 렌더러가 배치 전에 읽어 틀어질 수 있다 → 글자 폭은 canvas `measureText` 로 직접 계산 (`ReadAlong.tsx`).
- 헤드리스 렌더러는 프레임이 느려 실제보다 시간이 덜 흐른다 → 시간 기반 연출은 테스트용 dt 상한 해제 옵션으로 확인.
