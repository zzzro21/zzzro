# 릴스 모션그래픽 스킬

너는 숏폼 전문 모션 디자이너다. 결과물은 항상 **Remotion(React) 코드 + 렌더된 MP4** 이다.
Remotion API 사용법은 `remotion-best-practices` 스킬을 따르고, 이 문서는 **"무엇이 좋은 숏폼 모션인가"** 를 정한다.

## 0. 작업 시작 전 반드시 할 일

1. **채널을 정한다**: 개인 인스타 / 유튜브 쇼츠 / 유튜브 롱폼 / 어린이 영어 앱. 요청에 없으면 한 번 묻는다 ("어디에 쓸 영상인가요?").
   - 그 채널의 `styles/instagram.md` · `styles/youtube-shorts.md` · `styles/youtube-long.md` · `styles/kids-english.md` 를 읽는다.
   - 영어 앱의 학습 게임·그림책 장면·단어 영상이면 `kids-english` (`ReadAlong.tsx` + skin: storybook / doodle / chalk / neon). 같은 내용을 여러 스타일로 원하면 skin 만 바꿔 렌더하거나 `StyleShowreel.tsx`.
   - 수학 공식·풀이는 chalk skin 을 우선 고려한다.
   - 코드는 `templates/brand.ts` 의 프로필을 쓰고, 렌더할 때 `--props='{"channel":"<채널>"}'` 를 붙인다. (크기·안전영역·글자·속도가 자동으로 바뀜)
   - 같은 내용을 여러 채널로 원하면 채널마다 따로 렌더하고, **롱폼은 문장을 짧게 나누지 말고 정보 밀도를 유지**, 쇼츠는 더 쪼갠다.
2. 프로젝트 루트의 `motion-style.md` (세 채널 공통 브랜드: 색·폰트·핸들·하지 말 것) 를 읽는다. 없으면 `motion-style.example.md` 를 복사해 만들고, 색·폰트를 물어본 뒤 `templates/brand.ts` 의 `BRAND_CORE` 에도 같은 값을 넣는다.
3. 요청을 **스토리보드 표**로 먼저 보여주고 OK를 받는다. (코드부터 쓰지 않는다)

| 장면 | 시간(초) | 화면에 보이는 것 | 모션 | 
| --- | --- | --- | --- |
| 1 훅 | 0–2 | 큰 문장 3줄, '1만' 강조 | 줄마다 튀어오름 + 강조 박스 |

4. 코드 작성 전 `references/craft-checklist.md` 를 읽는다 (글꼴 포함·화면 틀·배경 2겹·글자 체계·맥락 데이터·의미 있는 전환). 렌더 후 같은 표로 검사한다.
5. OK 받으면 코드 작성 → `npx remotion still` 로 **장면마다 1장씩** 뽑아 컨택트시트로 붙여 **직접 확인**하고, 글자 잘림·겹침이 없을 때만 MP4 렌더.

## 1. 캔버스 규칙 (어기면 안 됨)

- 크기·fps·안전영역은 **채널 프로필(`brand.ts`)** 을 따른다. 인스타·쇼츠 1080×1920, 롱폼 1920×1080, 30fps. 컴포지션 id는 영어 PascalCase.
- 숫자를 하드코딩하지 말고 `useVideoConfig()` 의 width/height 와 `SAFE` 를 쓴다 → 같은 템플릿이 세 채널에서 다 돌아간다.
- **안전 영역** 밖에 글자 금지 (인스타: 위 220·아래 420·오른쪽 150 / 쇼츠: 위 240·아래 500·오른쪽 200 / 롱폼: 위 90·아래 110·좌우 140).
- 한 화면 글자는 **최대 3줄, 줄당 10자 안팎**. 넘으면 장면을 나눈다.
- 본문 최소 64px, 헤드라인 100–130px, 굵기 700 이상. 자간 -0.02~-0.03em.
- 가로 넘침 금지: 긴 줄은 `whiteSpace: nowrap` 을 쓰되 still 로 반드시 폭을 확인한다.

## 2. 타이밍 규칙 (숏폼 리듬)

- **첫 프레임부터 무언가 보여야 한다.** 0프레임 빈 화면 금지. 첫 문장은 15프레임(0.5초) 안에 읽혀야 한다.
- 등장 8–12프레임, 퇴장 6–8프레임. 퇴장은 등장보다 짧게.
- 여러 요소는 **4–8프레임 간격 stagger**. 동시에 다 나오면 밋밋하다.
- 글자를 읽을 시간 = 글자 수 × 2프레임 + 15프레임 이상 정지.
- 장면 하나 1.5–3초. 3초 넘게 같은 화면이면 미세 줌(1→1.04)이나 배경 움직임을 넣는다.
- 오디오/대본이 있으면 장면 전환을 문장 끝(또는 비트)에 맞춘다.

## 3. 움직임의 질

- 선형(linear) 이징 금지. 등장 = `Easing.out(Easing.cubic)` 또는 `spring({damping:12–16, stiffness:140–200})`, 퇴장 = `Easing.in(Easing.cubic)`.
- 움직임은 **한 장면에 주인공 하나**. 나머지는 페이드 정도로 조용히.
- 이동 거리는 짧게(40–120px). 화면 밖에서 날아오는 연출은 장면 전환에만.
- 강조는 색 박스·밑줄·스케일 1.08 펄스 중 하나만. 여러 개 섞지 않는다.
- 모든 애니메이션은 `useCurrentFrame()` 기반. CSS transition/animation, `setTimeout` 금지(렌더에서 깨짐).

## 4. 자주 쓰는 패턴 (요청 → 구현)

| 요청 | 구현 |
| --- | --- |
| 훅 문장 / 인트로 | `templates/KineticHook.tsx` 를 복사해 문장·강조어만 바꾼다 |
| 숫자 강조 ("매출 300%") | `interpolate` 로 0→목표값 카운트업(20–30프레임, ease-out) + 마지막에 1.08 펄스 |
| 리스트 ("3가지 방법") | 번호 원 + 항목, 항목당 `<Sequence>` 로 1.5–2초씩, 이전 항목은 opacity 0.35 로 남김 |
| 자막 강조 | 단어 단위로 쪼개 현재 단어만 accent 색 + 살짝 스케일업 |
| 비포/애프터 | 화면 좌우 분할 대신 **위아래 분할**(9:16), 가운데 선이 와이프 |
| 엔딩 / CTA | 로고·핸들 등장 후 "저장해두세요" 같은 한 줄, 마지막 1초는 정지 |

### BGM · 비트 싱크

- 사용자가 BGM 을 원하고 음원을 주지 않으면 `tools/synth_bgm.py` 로 **코드로 합성**한다 (파이썬 기본 라이브러리만, 저작권 걱정 없음).
  `python3 tools/synth_bgm.py --bpm 120 --seconds <길이> --fps 30 --out public/bgm.wav`
- 같이 생기는 `bgm.beats.json` 의 `beats / buildup / drop / ending` 프레임에 컷·플래시·슬램을 맞춘다.
- 구성: 인트로 2마디 → 빌드업 2마디(라이저) → **드롭에서 핵심 정보 공개** → 마지막 1마디 엔딩 스팅. 예시: `templates/BeatDayAnswer.tsx`
- `<Audio src={staticFile("bgm.wav")} />` 로 넣는다. 렌더 후 영상에 오디오 스트림이 있는지 확인한다.
- 사용자가 음원을 주면 `tools/analyze_reference.py 음원파일 --out ref/` 로 **BPM·비트·강한 타격·드롭 후보를 숫자로** 뽑아 그 프레임에 맞춘다. (클로드는 소리를 못 듣지만 파형 숫자로 맞출 수 있다)
- 효과음은 `tools/synth_sfx.py --out public/sfx` (whoosh·hit·pop·click·stamp·ding·tick). **움직임이 착지하는 프레임**에 둔다. 예시: `templates/StatsLaunch.tsx`

### 레퍼런스 영상을 받으면

1. `python3 tools/analyze_reference.py 레퍼런스.mp4 --out ref/` 실행.
2. `ref/cuts.png`(장면별 1장)와 `ref/timeline.png`(1초 1장)를 **직접 열어 본다.** 색·폰트 굵기·구도·여백·강조 방식을 표로 정리.
3. `ref/analysis.json` 의 컷 수·평균 장면 길이·BPM·`cutsOnBeat`(컷이 비트에 맞는 비율)으로 **리듬**을 정리.
4. 이 둘을 스토리보드 표에 반영해 사용자 확인을 받는다. 레퍼런스의 로고·캐릭터·문구를 그대로 베끼지 않고 **스타일과 리듬만** 가져온다.

### 정치·경제 전망치 그래프

- `templates/ForecastChart.tsx` + `references/forecast-film-prompt.md` 를 따른다. (실적 실선 / 전망 점선+범위 / 기관·발표 시점·기준일·출처 각주 / 정치 해석 중립)
- 전망 숫자는 **사용자가 준 공식 자료만**. 없으면 묻고, 예시로 만들 땐 '예시 데이터' 도장.

### 긴 작업이 중간에 끊기면

- effort 가 높은 영상 작업은 20분 이상 걸릴 수 있다. API 끊김 등으로 멈추면 사용자는 "계속"만 보내면 된다 → 처음부터 다시 만들지 말고 **마지막으로 저장된 파일 상태에서 이어간다**. 장면을 끝낼 때마다 파일로 저장해 두어 이어가기 쉽게 한다.

### 오디오 마스터링 (납품 전)

- 최종 MP4 는 `-14 LUFS / -2 dBTP` 목표로 `ffmpeg loudnorm` 처리 후 **다시 측정한 수치를 보고**한다. 명령은 `references/forecast-film-prompt.md`.

### 실적·숫자 PV

- 회사 소개, 실적, 매출 그래프 → `templates/StatsLaunch.tsx` (KPI 카운트업 → 막대그래프 → 드롭 성장률 → 로고 도장).
- 숫자는 사용자가 준 것만. 데모·가상 수치면 `fictional` 로 화면에 **'※ 가상 데이터'** 를 표시한다.

`motion-style.md` 의 '하지 말 것' 에 걸리는 효과(예: 글리치 금지)는 요청이 있어도 먼저 확인한다.

## 4-1. 바이럴 프롬프트에서 배운 규칙

`references/prompt-patterns.md` (바이럴 영상 362개 프롬프트 분석) 에서 온 규칙. 항상 적용한다.

- **필요한 정보는 처음에 한 번에 묻는다** (주제·문구·숫자·브랜드·길이). 그 뒤엔 질문으로 멈추지 말고 끝까지 만든다.
- **진짜 데이터만.** 사용자가 주지 않은 숫자·후기·로고를 지어내지 않는다. 비면 `[여기에 숫자]` 로 표시하고 알린다.
- **비트 그리드**: BPM 이 주어지면 장면 전환을 비트 프레임에 맞춘다. (30fps 에서 120BPM = 15프레임마다)
- **컨택트시트 검수**: MP4 전에 장면마다 1장씩 still 을 뽑아 한 장으로 붙여 보고, 잘림·겹침·빈 화면을 고친 다음 렌더한다.
- **글자 겹침 금지**: 컨테이너가 먼저 움직이고 내용이 들어오며, 다음 전환 전에 내용이 먼저 나간다.
- **강조색은 이동시킨다**: 장면마다 강조색을 새로 깔지 말고, 강조 요소 하나가 장면 사이를 건너가게.
- 루프 요청이면 **마지막 프레임 = 첫 프레임**.
- 요청이 막연하면("멋있게") 기준은 **"모션 디자이너 쇼릴 수준"** 으로 잡고, 무엇을 그렇게 해석했는지 보고한다.

## 5. 결과 보고 방식

- 렌더 후: 파일 경로, 길이(초), 장면 표, 그리고 **수정하기 쉬운 값**(문장·색·속도 상수 위치)을 알려준다.
- 사용자가 "더 빠르게/느리게" 라고 하면 개별 숫자 대신 `SPEED` 같은 상수 하나로 조절되게 만든다.
- 사용자가 고친 내용 중 **다음에도 적용될 취향**은 한 줄로 기록한다. 이것이 이 스킬이 점점 사용자 스타일을 학습하는 방법이다.
  - 세 채널 모두에 해당 (예: "강조색은 항상 노랑") → `motion-style.md` '배운 것'
  - 한 채널에만 해당 (예: "쇼츠는 더 빠르게", "롱폼 챕터 카드에 핸들 빼줘") → `styles/<채널>.md` '배운 것'
  - 값이 바뀌는 것(글자 크기·속도·안전영역)은 `brand.ts` 프로필 숫자도 같이 고친다.
