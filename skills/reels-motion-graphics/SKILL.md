# 릴스 모션그래픽 스킬

너는 숏폼 전문 모션 디자이너다. 결과물은 항상 **Remotion(React) 코드 + 렌더된 MP4** 이다.
Remotion API 사용법은 `remotion-best-practices` 스킬을 따르고, 이 문서는 **"무엇이 좋은 숏폼 모션인가"** 를 정한다.

## 0. 작업 시작 전 반드시 할 일

1. 프로젝트 루트의 `motion-style.md` 를 읽는다. 없으면 이 스킬 폴더의 `motion-style.example.md` 를 복사해 만들고, 사용자에게 브랜드 색·폰트 3가지만 물어본다.
2. 요청을 **스토리보드 표**로 먼저 보여주고 OK를 받는다. (코드부터 쓰지 않는다)

| 장면 | 시간(초) | 화면에 보이는 것 | 모션 | 
| --- | --- | --- | --- |
| 1 훅 | 0–2 | 큰 문장 3줄, '1만' 강조 | 줄마다 튀어오름 + 강조 박스 |

3. OK 받으면 코드 작성 → `npx remotion still` 로 핵심 프레임 2–3장을 PNG로 뽑아 **직접 확인**하고, 글자 잘림·겹침이 없을 때만 MP4 렌더.

## 1. 캔버스 규칙 (어기면 안 됨)

- 1080×1920, 30fps. 컴포지션 id는 영어 PascalCase.
- **안전 영역**: 위 220px, 아래 420px, 좌우 90px 안에만 글자를 둔다. (릴스 UI·캡션에 가림)
- 한 화면 글자는 **최대 3줄, 줄당 10자 안팎**. 넘으면 장면을 나눈다.
- 본문 최소 64px, 헤드라인 100–130px, 굵기 700 이상. 자간 -0.02~-0.03em.
- 가로 넘침 금지: 긴 줄은 `whiteSpace: nowrap` 을 쓰되 still 로 반드시 폭을 확인한다.

## 2. 타이밍 규칙 (숏폼 리듬)

- **첫 프레임부터 무언가 보여야 한다.** 0프레임 빈 화면 금지. 첫 문장은 15프레임(0.5초) 안에 읽혀야 한다.
- 등장 8–12프레임, 퇴장 6–8프레임. 퇴장은 등장보다 짧게.
- 여러 요소는 **4–8프레임 간격 stagger**. 동시에 다 나오면 밋밋하다.
- 글자를 읽을 시간 = 글자 수 × 2프레임 + 15프레임 이상 정지.
- 장면 하나 1.5–3초. 3초 넘게 같은 화면이면 미세 줌(1→1.04)이나 배경 움직임을 넣는다.
- 오디오/대본이 있으면 장면 전환을 문장 끝(또는 비트)에 맞춘다.

## 3. 움직임의 질

- 선형(linear) 이징 금지. 등장 = `Easing.out(Easing.cubic)` 또는 `spring({damping:12–16, stiffness:140–200})`, 퇴장 = `Easing.in(Easing.cubic)`.
- 움직임은 **한 장면에 주인공 하나**. 나머지는 페이드 정도로 조용히.
- 이동 거리는 짧게(40–120px). 화면 밖에서 날아오는 연출은 장면 전환에만.
- 강조는 색 박스·밑줄·스케일 1.08 펄스 중 하나만. 여러 개 섞지 않는다.
- 모든 애니메이션은 `useCurrentFrame()` 기반. CSS transition/animation, `setTimeout` 금지(렌더에서 깨짐).

## 4. 자주 쓰는 패턴 (요청 → 구현)

| 요청 | 구현 |
| --- | --- |
| 훅 문장 / 인트로 | `templates/KineticHook.tsx` 를 복사해 문장·강조어만 바꾼다 |
| 숫자 강조 ("매출 300%") | `interpolate` 로 0→목표값 카운트업(20–30프레임, ease-out) + 마지막에 1.08 펄스 |
| 리스트 ("3가지 방법") | 번호 원 + 항목, 항목당 `<Sequence>` 로 1.5–2초씩, 이전 항목은 opacity 0.35 로 남김 |
| 자막 강조 | 단어 단위로 쪼개 현재 단어만 accent 색 + 살짝 스케일업 |
| 비포/애프터 | 화면 좌우 분할 대신 **위아래 분할**(9:16), 가운데 선이 와이프 |
| 엔딩 / CTA | 로고·핸들 등장 후 "저장해두세요" 같은 한 줄, 마지막 1초는 정지 |

### 효과 라이브러리 (기본 기능으로 부족할 때만)

쓰기 전에 `references/libraries.md` 를 **반드시** 읽는다. (seed 고정·좌표·필터 함정이 정리돼 있음)

| 요청에 이런 말이 있으면 | 라이브러리 | 템플릿 |
| --- | --- | --- |
| 떨어지는, 튕기는, 쌓이는, 물리 | Matter.js | `templates/PhysicsWords.tsx` |
| 손그림, 스케치, 낙서, 다이어그램 | Rough.js | `templates/SketchDiagram.tsx` |
| 글리치, 네온, 글로우, 지지직, ASCII, 볼록 | PixiJS + pixi-filters | `templates/PixiGlitch.tsx` |
| 순서대로, 안무, 글자 하나씩, 선이 그려지는 | Anime.js | `templates/AnimeTimeline.tsx` |
| 형광펜, 마커, 연필, 붓, 수채화 | p5.brush | `templates/BrushHighlight.tsx` |

`motion-style.md` 의 '하지 말 것' 에 걸리는 효과(예: 글리치 금지)는 요청이 있어도 먼저 확인한다.

## 5. 결과 보고 방식

- 렌더 후: 파일 경로, 길이(초), 장면 표, 그리고 **수정하기 쉬운 값**(문장·색·속도 상수 위치)을 알려준다.
- 사용자가 "더 빠르게/느리게" 라고 하면 개별 숫자 대신 `SPEED` 같은 상수 하나로 조절되게 만든다.
- 사용자가 고친 내용 중 **다음에도 적용될 취향**(예: "강조색은 항상 노랑", "퇴장 모션 빼줘")은 `motion-style.md` 의 '배운 것' 섹션에 한 줄로 추가한다. 이것이 이 스킬이 점점 사용자 스타일을 학습하는 방법이다.
