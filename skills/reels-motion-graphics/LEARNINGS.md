# 클로드 모션그래픽 — 지금까지 학습한 것 (한 장 정리)

> 2026-11 기준. 사용자가 보낸 레퍼런스 영상·사례·피드백에서 배운 것을 한 문서로 모았다.
> 자세한 내용은 각 줄 끝의 파일을 본다. 이 문서가 목차이자 요약이다.

---

## 0. 한 줄 요약

**클로드는 영상을 '생성' 하지 않고 '코드로 그린다'.** (Remotion·HTML) → 글자·숫자·타이밍을 정확히 제어하고 매번 같은 결과가 나온다.
좋은 결과의 조건은 기술이 아니라 **① 채널에 맞는 형식 ② 마감 수준(질감·글꼴·전환) ③ 레퍼런스에서 뽑은 모션 문법** 세 가지였다.

## 1. 사용자 피드백에서 배운 것 (가장 중요)

| 피드백 | 배운 규칙 |
| --- | --- |
| "보내준 것과 퀄리티 차이가 너무 커" | 시제품이 아니라 작품 수준으로. 원인은 **마감**: 글꼴 대체, 단색 배경, 화면 틀 없음, 맥락 데이터 없음 → `references/craft-checklist.md` |
| "질감 차이도 커. 너무 유아틱해" | 굵은 검정 외곽선·원색·웃는 해·별·색종이 금지. **종이 결 + 흔들리는 손그림 선 + 색연필/마커 결 + 차분한 색** → `templates/handdrawn.tsx` |
| "완전히 덮어버리면 인스타에서 못 써" | 인스타는 **내 촬영본이 주인공**. 그래픽은 위에 **얹는** 오버레이 → `TalkingOverlay` |
| "사람은 그대로, 배경만 바뀌거나 사람 뒤로 글자가 지나가는 정도" | 누끼(사람만 오려내기) + 배경 교체 + 뒤 글자 → `tools/person_matte.py`, `CutoutStage` |
| "하나의 코드로 여러 스타일로 변환되면 좋겠다" | **내용과 스타일(skin) 분리** → `kidsSkins.tsx`, `StyleShowreel` |
| "유튜브 쇼츠 / 롱폼 / 개인 인스타 3가지로 나눠서" | 채널 프로필 + 채널별 스타일 문서 → `templates/brand.ts`, `styles/*.md` |

## 2. 작업 원칙 (모든 영상 공통)

1. **채널부터 정한다** — 개인 인스타 · 유튜브 쇼츠 · 유튜브 롱폼 · 어린이 영어 앱. 렌더 시 `--props='{"channel":"…"}'`.
2. **스토리보드 표 먼저** → 폰트·효과·모션 A/B/C 중 선택 → OK → 코드. (2026-11-27 항상)
3. **컨택트시트 검수** — 장면마다 1장 뽑아 보고 잘림·겹침·글꼴을 확인한 뒤 MP4.
4. **진짜 데이터만** — 숫자·후기·로고를 지어내지 않는다. 예시면 화면에 "예시/가상 데이터" 표기.
5. **결정적 렌더** — 랜덤은 seed 고정, 실제 시계 금지, 프레임 = 순수 함수. (`references/libraries.md`)
6. **글꼴은 프로젝트에 포함** — 없으면 조용히 기본 글꼴로 바뀐다(실제로 겪음). → `templates/fonts.ts`
7. **끊기면 "계속"** — 긴 작업은 저장된 상태에서 이어간다.
8. **피드백은 기록** — 공통 취향은 `motion-style.md`, 채널 취향은 `styles/<채널>.md` 의 '배운 것'.

## 4. 레퍼런스에서 배운 모션 문법

### 4-1. 토킹 릴스 (인스타, 가장 최근·가장 중요) → `references/motion-grammar-talking.md`
1. 위젯은 **한 아이디어 동안 유지**(3~8초), 자막만 바뀐다.
2. **전 → 후**: 가는 흰 선으로 그려지며 등장 → 자막 핵심어 순간 **분홍으로 채워짐** + 링 펄스·빗금.
3. 여러 위젯이 아래 줄 좌·중·우에 **동시에**.
4. 카운터는 핵심어 순간 시작, ease-in-out 약 1초 (측정값 0→2→6→14→27→43→54→61→64→65).
5. 퇴장은 블러+페이드. 6) 댓글 CTA: 입력창 그려짐 → 키워드 타이핑 → 전송 → 하트.
7. 배울 것은 **움직임 문법**이지 분홍색이 아니다(11-27 사용자: "꼭 분홍색만 사용하라는 뜻은 아니야"). 강조색 한 가지 + 흰색 + 어두운 반투명 구성으로, 강조색은 채널·영상에 맞춰 바꾼다(`accent` 값). 레퍼런스는 분홍 #EC5096 근처. 같은 영상이 다시 오면 새로 분석하지 말고 이 템플릿부터(11-27 재요청). 아직 없는 위젯: timer 길이 막대(5초→30초).

### 4-2. 바이럴 모션 프롬프트 362개 분석 → `references/prompt-patterns.md`
- 숫자로 스펙, "쇼릴처럼 전력으로", **컷은 비트에**, 색 3개·한 장면 한 메시지, 진짜 데이터만, 검수 후 렌더.
- 세로(9:16) 모션은 362개 중 63개 → 아직 빈 자리.

### 4-3. 마감 수준 (원본 vs 우리 첫 결과) → `references/craft-checklist.md`
글꼴 · 화면 틀 · 배경 2겹 · 글자 3단계 · 맥락 데이터 · 의미 있는 전환 · 효과가 틀 밖으로 · 슬로모션 1번 · 질감 · 유아틱함 · 스타일 확장 (17항목)

## 7. 실제로 겪은 함정 (다시 안 하기)

- 글꼴 미포함 → 전부 Inter 로 렌더됨.
- 화면 위치(DOM)를 읽어 배치 → 렌더러가 배치 전에 읽어 틀어짐. 글자 폭은 `measureText` 로 계산.
- 라이브러리 자체 시계(`performance.now`)·랜덤 → 렌더마다 다른 그림.
- Pixi `filterArea` → 필터 겹치면 사라짐. p5.brush 좌표 (0,0) = 화면 가운데.
- 반투명 입자 과다 → 브라우저 멈춤. 입자 수·크기 상한.
- 셀카 누끼 모델은 뒤쪽 작은 사람을 반쯤 잡아 깜빡임 → 주인공만 남기기 (경계 다듬기 **전** 원래 마스크로 분리).
- 효과음 위주 짧은 영상은 -2 dBTP 한도 때문에 -14 LUFS 까지 못 올라갈 수 있음 → 측정값 그대로 보고.
- 헤드리스 브라우저에서 WebGPU 화면 출력 불가 → WebGL 로 검증, 실기기는 자동 전환.
